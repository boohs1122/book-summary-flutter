# 문서 규칙

## 톤

보고서 문체로 쓴다. 1인칭(나, 내가, 우리)과 2인칭(너, 당신)을 쓰지 않고,
주관적 감상을 넣지 않는다. 결정 사항과 근거를 서술한다.

## 위치

기획 문서는 이 저장소의 `docs/`에 단일 보관한다. 서버 저장소는 링크로 참조한다.

| 문서 | 담는 것 |
|---|---|
| `docs/01_기획.md` | 무엇을 만들지, 확정 스펙, 설계 결정과 근거 |
| `docs/02_화면흐름.md` | 화면 구성, 사용자 액션, 예외 분기 |
| `docs/03_API명세.md` | 엔드포인트 계약, 스키마, 에러 |
| `docs/04_개발규약.md` | 작업 방식, 품질 기준, 구조 규칙 |

## 갱신 규칙

- 같은 값을 여러 문서에 적지 않는다. 필요하면 링크로 참조한다
- 실측 후 조정할 값은 `docs/01_기획.md` 8장에서 일괄 관리한다
- 결정이 바뀌면 관련 문서를 모두 함께 고친다. 한 곳만 고쳐 모순을 남기지 않는다
- 기획 문서의 결정 사항을 임의로 바꾸지 않는다. 사용자 확인을 거친다

## 기획서 HTML

`docs/기획서.html`과 `docs/화면프로토타입.html`은 열람용이며 원본은 마크다운이다.
마크다운을 고친 뒤 HTML을 갱신한다.

# BookSummaryApp 화면 흐름

작성일: 2026-09-20
상태: 초안 (책 > 회차 구조 반영)
관련 문서: [01_기획.md](01_기획.md), [03_API명세.md](03_API명세.md)

## 1. 화면 목록

| # | 화면 | 역할 |
|---|---|---|
| S1 | 홈 · 책 목록 | 책 카드 목록, 신규 촬영 시작 |
| S2 | 책 상세 · 회차 목록 | 한 권의 회차 목록, 회차 추가 |
| S3 | 이미지 선택 | 촬영 및 갤러리 선택, 순서 조정, 장수 관리 |
| S4 | OCR 진행 | 기기 내 텍스트 추출 진행률 표시 |
| S5 | 텍스트 확인 | 추출 결과 검토 및 편집 |
| S6 | 책 선택 | 저장할 책 지정 또는 신규 생성 |
| S7 | 요약 생성 대기 | 서버 작업 상태 폴링 |
| S8 | 요약 보기 | 요약 결과 표시, 퀴즈 진입 |
| S9 | 퀴즈 풀이 | 문항 순차 응답 |
| S10 | 채점 결과 | 점수, 정오답, 해설 표시 |

S6은 홈에서 바로 촬영을 시작한 경우에만 거친다. 책 상세에서 시작하면
대상 책이 이미 정해져 있으므로 S5에서 S7로 직행한다.

## 3. 화면 상세

### S1. 홈 · 책 목록

**구성**
- 책 카드: 제목, 회차 수, 마지막 학습일, 최근 점수
- 플로팅 버튼: 바로 찍기

검색은 1차에서 제공하지 않는다. 동작하지 않는 검색 아이콘을 두지 않는다.

**액션**
- 책 카드 선택 → S2
- 바로 찍기 → S3 (책 미지정 상태로 시작)
- 카드 스와이프 → 책 삭제 (회차 전체 삭제 경고 후 확인)

**정렬**
- 마지막 학습일 내림차순. 최근에 본 책이 위로 온다

**예외**
- 기록 없음: 빈 상태 화면. 첫 촬영을 안내하는 문구와 버튼
- 목록 조회 실패: 재시도 버튼

**API**: `GET /books`, `DELETE /books/{bookId}`

---

### S2. 책 상세 · 회차 목록

**구성**
- 상단: 책 제목, 회차 수, 총 글자 수
- 회차 카드: `N회차`, 요약 제목, 생성일, 퀴즈 응시 배지, 상태 배지
- 플로팅 버튼: 회차 추가

회차 제목은 요약의 `title`을 사용한다. 요약이 없는 회차(진행 중·실패)는
원문 앞부분을 대체 표기한다.

**액션**
- 회차 카드 선택 (`DONE`) → S8
- 회차 카드 선택 (`PROCESSING`) → S7로 이동해 폴링 이어받기
- 회차 카드 선택 (`FAILED`) → 재시도 확인 후 요약 재요청, S7로 이동
- 회차 추가 → S3 (해당 책으로 지정된 상태)
- 카드 스와이프 → 회차 삭제

**정렬**
- 회차 번호 오름차순. 책은 순서대로 읽는 대상이다

**예외**
- 마지막 회차를 삭제해도 책은 유지한다. 빈 책 상태를 허용하되 목록에서는
  회차 0으로 표시하고, 사용자가 직접 삭제할 수 있게 한다

**API**: `GET /books/{bookId}`, `POST /documents/{documentId}/retry`

---

### S3. 이미지 선택

**구성**
- 선택된 이미지 썸네일 그리드 (순서 번호 표시)
- 카메라 촬영 버튼 / 갤러리 선택 버튼
- 현재 장수 표시 (예: `3 / 8`)
- 대상 책 표시 — 책이 지정된 경우에만 상단에 노출
- 안내 문구: 한 페이지씩 촬영 시 인식률이 높음
- 하단 고정 버튼: 텍스트 추출

**액션**
- 촬영 또는 갤러리 선택 → 목록에 추가
- 썸네일 길게 눌러 순서 변경 (페이지 순서가 텍스트 순서를 결정)
- 썸네일 X 버튼 → 제거
- 텍스트 추출 → S4

**규칙**
- 최대 8장. 초과 선택 시도 시 스낵바 안내 후 무시
- 0장이면 추출 버튼 비활성
- 펼침면(양쪽 페이지) 촬영도 허용. 좌우 인식 순서 보정은 2차 과제

**예외**
- 카메라·저장소 권한 거부: 설정 이동 안내 다이얼로그

---

### S4. OCR 진행

**구성**
- 진행률 인디케이터 (`2 / 5 장 처리 중`)
- 취소 버튼

**동작**
- 기기 내에서 순차 처리. 장당 리사이즈(긴 변 1600px) 후 ML Kit 호출
- 페이지 순서대로 텍스트를 이어 붙임

**분기**
- 누적 100자 미만: 실패로 판정. 안내 후 S3 복귀
- 100자 이상: S5로 이동
- 10,000자 초과: 초과분 절단, S5에서 안내 배너 표시

**예외**
- 취소 선택 시 S3 복귀. 처리된 결과는 폐기

---

### S5. 텍스트 확인

**구성**
- 추출 텍스트 표시 영역 (기본 접힘, 앞부분 일부만 노출 + 펼치기)
- 편집 가능한 입력 영역
- 글자 수 표시
- 절단 발생 시 안내 배너
- 버튼: 다시 찍기 / 요약하기

**목적**
- OCR 오류를 사용자가 직접 확인·수정해 요약 품질을 확보
- 불필요한 LLM 호출을 사전에 차단

**액션**
- 요약하기
  - 책이 지정된 경우 → 서버 전송 후 S7
  - 책이 미지정인 경우 → S6
- 다시 찍기 → S3 복귀

**오프라인**
- OCR과 텍스트 편집은 연결 없이 동작한다
- 요약하기 선택 시점에만 연결을 확인하고, 실패 시 스낵바 안내 후 재시도
- 편집 내용은 화면에 유지되므로 재입력이 필요 없다
- 기기 임시 저장은 하지 않는다

**API**: `POST /documents` → `{ jobId }` 반환

---

### S6. 책 선택

홈에서 바로 촬영을 시작한 경우에만 거치는 화면이다.

**구성**
- 기존 책 목록 (최근 학습 순)
- 상단 고정 항목: 새 책 만들기
- 필터 입력 — 목록이 길어졌을 때 이름으로 좁힌다

필터는 같은 화면에서 목록이 줄어드는 인라인 동작이며, 별도 결과 화면을 갖는
검색과 구분한다. 책 목록이 길어지는 유일한 지점이라 1차부터 제공한다.

**액션**
- 기존 책 선택 → 해당 책에 회차로 추가, S7로 이동
- 새 책 만들기 → 제목 입력 다이얼로그 → 책 생성 후 S7로 이동

**규칙**
- 책은 첫 회차와 함께 생성된다. 빈 책을 먼저 만드는 경로는 두지 않는다
- 제목이 비어 있으면 생성 버튼 비활성
- 같은 제목의 책을 막지 않는다. 판단은 사용자 몫이다

**예외**
- 뒤로가기: S5로 복귀하며 편집한 텍스트를 유지한다

**API**: `GET /books`, `POST /books`

---

### S7. 요약 생성 대기

**구성**
- 진행 인디케이터, 안내 문구
- 경과 시간 표시
- 취소 버튼

**동작**
- 2초 간격으로 작업 상태 조회
- `DONE` 수신 시 S8로 이동
- 앱 복귀 시 저장된 jobId로 상태를 재조회해 복구

**취소 동작**

취소는 화면에서 벗어나는 것만 의미한다. 서버 작업은 계속 진행되어 결과가
저장되며, 취소 API는 두지 않는다. 이미 LLM 호출이 시작된 뒤라 중단해도
비용이 절약되지 않고, S8 이탈 처리와 규칙이 일치해 구현이 단순해진다.
취소한 회차는 해당 책의 목록에 진행 중 상태로 나타난다.

**예외**
- `FAILED`: 실패 사유 표시, 재시도 버튼 (S5 텍스트 유지)
- 60초 초과: 지연 안내 문구로 전환하되 폴링 유지
- 네트워크 단절: 재연결 시 폴링 재개

**API**: `GET /jobs/{jobId}` (반복)

---

### S8. 요약 보기

**구성**
- 상단: 책 제목 · N회차 (상위 맥락을 항상 보여준다)
- 제목 (한 문장 요약)
- 핵심 항목 목록 — 유형 라벨 + heading + detail
  - 좌측 색 스트라이프와 작은 라벨 칩으로 유형을 구분한다
  - 색은 스트라이프와 칩에만 쓰고 본문에는 적용하지 않는다. 본문까지 물들면 가독성이 떨어진다
  - 유형: 정의 · 원리 · 원인 · 비교 · 주의 · 예시
- 용어 목록 섹션 (term / meaning)
- 원문 보기 접이식 영역
- 하단 버튼: 퀴즈 풀기 / 다시 풀기

**액션**
- 퀴즈 풀기 → 퀴즈 생성 요청 후 S9
  - 최초 진입 시 생성 요청, 재진입 시 저장된 퀴즈를 그대로 조회
  - 회차당 퀴즈는 1세트만 보유한다. 재생성하지 않는다
- 책 제목 영역 선택 → S2 (해당 책의 회차 목록)
- 이전 응시 기록이 있으면 점수 배지와 결과 보기 진입점 노출

**퀴즈 생성 대기 처리**

퀴즈 생성도 LLM 호출이므로 즉시 완료되지 않는다. 별도 대기 화면으로
전환하지 않고 S8에 머문 채 버튼 내에서 대기를 표현한다.

| 단계 | 처리 | 버튼 상태 |
|---|---|---|
| 1 | 버튼 선택, 생성 요청 전송 | 비활성 + 스피너 |
| 2 | 응답 200 (기존 퀴즈 존재) | 스피너 유지, 4단계로 이동 |
| 3 | 응답 202, 2초 간격 상태 조회 | 스피너 유지 |
| 4 | 퀴즈 조회 완료 | 원복 후 S9 전환 |

화면을 유지하므로 대기 중에도 요약 열람이 가능하다. 재진입 시에는
기존 퀴즈를 반환받아 1초 이내에 전환된다.

**예외**
- 퀴즈 생성 실패: 요약 화면은 유지한 채 버튼 원복, 스낵바 안내 및 재시도
- 대기 중 이탈: 서버 작업은 계속된다. jobId를 로컬에 보관해 재진입 시 상태를 재조회
- 진행 중 작업 존재(409): 반환된 jobId로 폴링을 이어받는다

**조정 대상**: 생성 소요 시간이 10초를 초과하면 진행 문구 추가 또는
대기 화면 전환 방식을 재검토한다.

**API**: `GET /documents/{documentId}`, `POST`·`GET /documents/{documentId}/quiz`

---

### S9. 퀴즈 풀이

**구성**
- 진행 표시 (`2 / 3`)
- 문항 텍스트
- 4지선다 선택지
- 이전 / 다음 이동, 마지막 문항에서 제출

**규칙**
- 풀이 중에는 정답과 해설을 노출하지 않음
- 미응답 문항이 있으면 제출 시 확인 다이얼로그

**액션**
- 제출 → 채점 후 S10

**예외**
- 이탈 시도: 진행 상황 소실 경고 다이얼로그

---

### S10. 채점 결과

**구성**
- 점수 요약 (`3문제 중 2문제 정답`)
- 문항별 카드: 문항, 선택한 답, 정답, 해설
- 오답 강조 표시
- 버튼: 요약으로 돌아가기 / 다시 풀기

**액션**
- 결과를 서버에 저장
- 다시 풀기 → S9 재진입. 동일 문항을 다시 푼다 (새 문항 생성 없음)
- 재응시 결과는 기존 결과를 덮어쓰지 않고 별도 레코드로 누적

**API**: `POST /quizzes/{quizId}/results`

## 4. 공통 규칙

| 항목 | 처리 |
|---|---|
| 로딩 | 전체 화면 인디케이터 대신 영역 단위 표시. 버튼은 비활성 + 스피너 |
| 네트워크 오류 | 스낵바 안내 + 재시도 수단 제공. 화면 이탈 없음 |
| 빈 상태 | 목록·결과가 없는 모든 화면에 안내 문구와 다음 행동 버튼 배치 |
| 뒤로가기 | S4, S7, S9는 진행 상황 소실 경고 후 이동 |
| 작업 복구 | 진행 중 jobId를 로컬에 보관. 앱 재실행 시 상태 조회로 복구 |
| 오프라인 | 기기 내 처리는 동작. 서버 요청 시점에만 연결 확인 후 안내 |
| 상위 맥락 | 회차를 다루는 모든 화면에 책 제목을 노출한다 |

## 5. 퀴즈 재응시 정책

| 항목 | 결정 |
|---|---|
| 문항 재사용 | 회차당 퀴즈 1세트. 재응시 시 동일 문항을 그대로 사용 |
| 재생성 | 하지 않음. LLM 호출은 최초 1회로 제한 |
| 결과 보관 | 응시할 때마다 `QuizResult` 레코드를 누적 생성 |
| 최신 점수 | 가장 최근 응시 결과를 목록·요약 화면의 배지에 표시 |

동일 문항 반복은 복습 용도에 부합하며, 무료 티어 소진을 억제한다.
문항 재생성이 필요해지면 별도 기능(문제 새로 뽑기)으로 분리해 검토한다.

## 6. 후속 확정 대상

- 각 화면의 실제 레이아웃 (와이어프레임)
- 문구 문안 (에러 메시지, 빈 상태 안내)
- 검색 도입 시점 (설계안은 01 문서 8장)
- 책 단위 통합 퀴즈 진입점 위치
- 회차 순서 변경 허용 여부
